Lessons learned #1 — multi-agent collaboration & tooling

2026-07-26, written mid-W6 (build-doctrine window): four honest golden re-records, two falsified hypotheses, three gate-caught defects in one arc. Twin of lessons-learned-1.md.

Part 1 — Collaborating with other agents: what works

Adversarial gates catch what tests cannot — run them on PUSHED shas
Slice-1a: fixtures 7/7, twins 11/11, clean-clone 0-fail — and behaviorally DORMANT (0.9% coverage); only the 25-seed measurement caught it. The 1b fix passed review + a 3-seed probe — the sweep caught the M3 collapse (25 → 15.25). Tests prove the mechanism; sweeps prove the effect.
Independent reproduction beats trust
The reviewer re-derives goldens under lune from git rather than believing commit messages. It turned "scary winner-flip" into "reproduces byte-identical JS==Luau = deterministic butterfly, not a bug".
Queue = obligation · mail = context · status = presence
Work travels as queue items (acked ≠ done), verdicts as mail (at-least-once, ack what you acted on), presence as one status line per lane. Blurring them stalls lanes silently — the session's one ambiguity (a stale "waiting" line over a taken queue item) cost a flag round-trip.
Locks are leases; pathspec-scope every commit
Three agents, one tree: 45-min lock leases + explicitly-named files per commit. git stash push -- <files> saved a lane's WIP through a rebase. Corollary: casual git checkout <file> wiped an uncommitted change once — never do it on a shared tree.
Serialize stamp-shifting golden windows
Two windows that both touch rulesetHash data ripple the SAME createGame-stamp goldens — whoever runs the sim picks up the other's uncommitted change. Only golden-neutral work parallelizes.
Task openings: "git pull origin dev_night — expect tip <sha>"
Removes the whole reviewed-the-wrong-tree failure class for remote-clone lanes.
Blocked lanes raise their hand; silence is never a status
The blocked→ruling loop resolved the M3 regression in one cycle because the lane mailed BLOCKED with the full floor table instead of idling.
Report state, not agency
"M3-pop 15.5 FAILS floor 22, do not tag" is routable without reading the body. Build-log voice keeps verdicts machine-checkable.
Proactive lanes accelerate — when they hold no design authority
Proactive W5 gate + proactive sweeps sped the arc; safe because measure/review lanes label their output "advisory / your call".
User rulings are design inputs — fetch them at the fork
W4 scope, the 1c knob, the 1d role-discipline ruling: each one targeted question with concrete options and a recommendation, at the moment the fork was reached — not forgiveness afterwards.

Part 1b — What does not work

Green tests as evidence of effect
Effects are measured by direct count in the wild config, never inferred from passing fixtures or moved hashes.
Small-sample probes as gate evidence
1 seed said 73%, 3 seeds said fine, 25 seeds said FAIL. Probes choose between variants; only the canonical sweep gates. Re-learned twice in one window.
Inline mail bodies / heredoc-into-send
Hook-blocked: they stream bodies through transcripts. Always Write the body file, then send --body-file.
Assuming a lane's environment
A lane lost Write/lune approvals mid-arc. Fix: commit probes into the repo (debugging/probe-peace.js) so remote lanes only need read+run.
"Known flakes" unread
Every not-ok name gets read; the one tolerated local red (B13 witness) is verified-gitignored and re-verified each window.

Part 2 — /tmp scratchpad vs ./debugging

Session scratchpad (/tmp/…/scratchpad/)
One-shot diagnostics, mid-calibration probe variants, mail body files. Dies with the session — right for exploration, fatal for anything a remote lane or future session needs.
./debugging/ (committed)
Probes a write-blocked remote lane must run, witnesses reused across slices, measurement configs worth repeating. The moment a scratch probe proves useful twice, commit it. The standing scripts (t.sh, peek.sh, shoot.sh, killport.sh, triage.sh) replace ad-hoc pipes — use them.

Part 2c — Patterns to keep

Fixture-first, always
The pre-implementation failure is part of the evidence.
Measure in the canonical config
Golden-seed sims are for determinism; effect sizes come from 7-civ medium.
Honest re-record headers
Every pin block states what moved, why, the classification, and the probe numbers — the file is the audit trail.
Background long runs; read outputs from files
And never let tail eat the failing test's name.
Kill contaminated runs
A baker/sim started before a knob flip is poisoned data — stop it, don't reason about it.
Surgical edits over whole-file rewrites
Script-driven JSON rewrites re-serialize and churn the diff; use targeted edits.
Skills for recurring asks
sync-pass, marker, status-report: checklists beat memory for anything asked verbatim more than twice.

The meta-lesson

Where the expensive defects actually live
Never in the code the tests covered — in the interactions (garrison floor × threat gate × settler loop) that only whole-game measurement exposes. The system that catches them: fixture-first tests (mechanism) + twins gate (portability) + 25-seed sweeps (effect) + independent review (honesty) + a user ruling at each design fork (intent). Remove any leg and a plausible-but-wrong change ships.
